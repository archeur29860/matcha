---
title: "Authentification"
description: "Connexion d'un utilisateur et obtention d'un jeton JWT."
---

Blueprint `auth_bp`, préfixe `/api/auth`. Code : `back-matcha/routes/authenticate_bp.py` et `back-matcha/services/authenticate_service.py`. Voir aussi [le fonctionnement de l'authentification](/backend/authentification).

## Se connecter

`POST /api/auth/`

Authentifie un utilisateur et renvoie un jeton d'accès JWT généré par Flask-JWT-Extended.

<ParamField body="email" type="string" required>
  Adresse email de l'utilisateur.
</ParamField>

<ParamField body="password" type="string" required>
  Mot de passe en clair, comparé au hash stocké avec `check_password_hash`.
</ParamField>

```bash
curl -X POST http://localhost:5000/api/auth/ \
  -H "Content-Type: application/json" \
  -d '{"email": "jean.dupont@example.com", "password": "monMotDePasse123"}'
```

Réponse `200` :

```json
{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": "<uuid>",
      "email": "jean.dupont@example.com",
      "username": "jdupont",
      "first_name": "Jean",
      "last_name": "Dupont"
    }
  },
  "error": null
}
```

<ResponseField name="access_token" type="string">
  JWT dont l'identité est l'UUID de l'utilisateur. À envoyer dans l'en-tête `Authorization: Bearer <token>` pour les routes protégées, comme [`/api/connected/`](/api/connected).
</ResponseField>

| HTTP | Code | Cause |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Corps JSON absent, `email` ou `password` manquant |
| 400 | `VALIDATION_ERROR` | `Invalid email or password` (même message dans les deux cas pour éviter l'énumération de comptes) |

<Note>
  Il n'existe ni route de déconnexion côté serveur ni jeton de rafraîchissement : la déconnexion supprime simplement le jeton côté client.
</Note>
