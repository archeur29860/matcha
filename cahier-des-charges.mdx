Ce document reprend les règles et exigences fonctionnelles du projet Matcha telles que définies dans le README original. Les sections technologiques et de référence ont été résumées ou omises ; seule la spécification métier est préservée.

## Règles à respecter

- Aucune erreur, warning ou notice ne doit être produite par l'application.
- Aucune vulnérabilité de sécurité n'est autorisée.
- Libre choix du langage de programmation.
- On peut se servir de bibliothèques d'interface (React, Angular, Vue, Bootstrap, Semantic, ou toute combinaison de celles-ci).
- La base de données doit contenir un minimum de 500 profils distincts.
- Serveur web de notre choix.
- L'application entière doit être compatible avec au moins les dernières versions de Firefox et Chrome.
- Les pages doivent avoir un en-tête, une section principale et un pied de page.
- Adaptable aux mobiles.

## Inscription et connexion

Après l'inscription, l'utilisateur doit recevoir un email avec un lien unique pour vérifier son compte.

### Inscription

Les champs requis sont :

- adresse email
- nom d'utilisateur
- nom de famille
- prénom
- mot de passe sécurisé

### Connexion

Tableau de connexion :

- nom d'utilisateur
- mot de passe

Lien de réinitialisation :

- adresse email

Une fois connecté, un bouton de déconnexion est disponible.

## Profil utilisateur

Une fois connectés, les utilisateurs doivent compléter leur profil avec les éléments suivants :

- **Genre**
- **Préférences sexuelles**
- **Biographie**
- Liste d'**intérêts** utilisant des tags (par exemple, #vegan, #geek, #piercing, etc.), qui doivent être réutilisables
- Maximum **5 photos**, dont une désignée comme photo de profil

Les utilisateurs doivent pouvoir **modifier ces informations** à tout moment : leur nom de famille, prénom et adresse email.

Le profil affiche également :

- **Qui a consulté** leur profil
- **Qui les a "likés"**
- Une **note de popularité** publique
- **Localisation** via le positionnement GPS jusqu'à leur quartier, avec leur **consentement explicite**. La localisation se limitera à la ville ou au code postal. Si un utilisateur refuse le suivi de localisation GPS, il doit pouvoir saisir manuellement une approximation (ville ou code postal) pour utiliser les fonctionnalités de matching. Cette saisie manuelle de la localisation est requise pour que l'application fonctionne correctement. Les utilisateurs doivent également avoir la possibilité de modifier leur localisation dans leur profil à tout moment.

## Navigation

Les utilisateurs ont accès à une liste de profils suggérés en fonction de leurs préférences :

- **Préférences sexuelles** (bisexuel par défaut)
- La **proximité** avec la localisation géographique de l'utilisateur
- Le plus grand nombre de tags partagés
- La "note de popularité" la plus élevée
- La priorité doit être donnée aux utilisateurs de la même zone géographique
- **Tri** par âge, localisation, "note de popularité" et tags communs
- Les utilisateurs doivent pouvoir **filtrer** la liste en fonction de l'âge, de la localisation, de la "note de popularité" et des tags communs

## Recherche

Recherche avancée en fonction :

- D'une tranche **d'âge** spécifique
- D'une plage de "note de **popularité**"
- D'une **localisation**
- D'un ou plusieurs **tags** d'intérêt

## Consultation de profil

Les utilisateurs peuvent consulter les autres profils. Toutes les informations sont disponibles à part l'**adresse email** et bien sûr le **mot de passe**.

Le profil visité est enregistré dans l'historique du visiteur.

Lors d'une consultation, l'utilisateur peut :

- **"Liker"** la photo de profil. Lorsque deux utilisateurs se "likent" mutuellement, ils seront considérés comme "connectés" et pourront commencer à discuter.
- Si l'utilisateur n'a pas de photo de profil, il n'apparaît pas dans la navigation et n'a pas accès au service.
- **Retirer un "like"** précédemment donné. Cela empêchera les notifications ultérieures de cet utilisateur, et la fonction de chat entre eux sera désactivée.
- Consulter la "note de popularité" d'un autre utilisateur.
- Voir s'il est **actuellement en ligne** ou la date et l'heure de sa **dernière connexion**.
- **Signaler** un utilisateur comme "faux compte", "scam" ou "problématique".
- **Bloquer un utilisateur**. Un utilisateur bloqué n'apparaîtra plus dans les résultats de recherche et ne générera plus de notifications. De plus, discuter avec lui ne sera plus possible.

Les utilisateurs doivent clairement voir si le profil qu'ils consultent les a **"likés"** ou s'ils sont déjà **"connectés"**. Ils doivent également avoir la possibilité de **"unliker"** ou de se déconnecter de ce profil.

## Chat

Lorsque deux utilisateurs sont connectés, ils peuvent clavarder en **temps réel** (**délai max 10 s**).

Une popup de notification est disponible depuis n'importe quelle page.

## Notifications

Les utilisateurs doivent recevoir des notifications en temps réel (délai max 10 s) sur n'importe quelle page pour les événements suivants :

- Lorsqu'ils reçoivent un **"like"**
- Lorsque leur profil a été **consulté**
- Lorsqu'ils reçoivent un **message**
- Lorsqu'un utilisateur qu'ils ont **"liké"** les **"like"** également en retour
- Lorsqu'un utilisateur connecté les **"unlike"**

## Cybersécurité

Les vulnérabilités de sécurité suivantes ne sont pas tolérées :

- Stocker des mots de passe en clair dans la base de données
- Permettre l'injection de HTML ou JavaScript dans des variables non protégées
- Permettre le téléchargement de contenu non autorisé
- Permettre les attaques par injection SQL
