---
title: "Seed de la base"
description: "Génération automatique des faux profils au démarrage du backend."
---

Le cahier des charges impose au moins 500 profils distincts. Le package `back-matcha/seed/` remplit la base avec des données factices générées par [Faker](https://faker.readthedocs.io) (locale `fr_FR`).

## Déclenchement

`back-matcha/entrypoint.sh` lance le seed avant l'API :

```bash
python ./seed/__init__.py
exec python app.py
```

`seed/__init__.py` compte les lignes de la table `users`. Le seed ne s'exécute que si ce nombre est inférieur ou égal à 500, ce qui évite de régénérer les données à chaque redémarrage.

## Nombre de profils

Le nombre d'utilisateurs créés vient de la variable d'environnement `NB_FAKE_PROFILE`, transmise au conteneur `app` par `docker-compose.yaml`.

```bash .env
NB_FAKE_PROFILE=500
```

## Ordre d'exécution

<Steps>
  <Step title="Utilisateurs (seed_users.py)">
    Prénom, nom, nom d'utilisateur (`<user_name>_<0-800>`), email sans accents, mot de passe aléatoire de 20 caractères haché avec Werkzeug, `last_connection` dans les 30 derniers jours, `is_online` aléatoire, `signaled` tiré d'une distribution triangulaire entre 0 et 5.
  </Step>
  <Step title="Photos (seed_pictures.py)">
    Entre 0 et 5 photos par utilisateur, choisies au hasard parmi les fichiers de `back-matcha/pictures/`.
  </Step>
  <Step title="Profils (seed_profiles.py)">
    Date de naissance pour un âge entre 18 et 60 ans, genre, préférences (une seule dans 80 % des cas, sinon `Male` et `Female`), bio et ville tirées de listes prédéfinies, 0 à 5 tags parmi les identifiants 1 à 70, popularité entre 0 et 5, photo de profil choisie parmi les photos de l'utilisateur.
  </Step>
  <Step title="Interactions (seed_interactions.py)">
    Entre 0 et 40 interactions par utilisateur (`Liked`, `Viewed` ou `Blocked`) vers des utilisateurs aléatoires, datées des 30 derniers jours.
  </Step>
  <Step title="Matches (seed_matches.py)">
    Une requête SQL crée un match pour chaque paire d'utilisateurs qui se sont likés mutuellement.
  </Step>
</Steps>

<Note>
  Un utilisateur sans photo n'a pas de `picture_profile_index` et n'apparaît donc pas dans la liste des profils suggérés.
</Note>

## Compte de test

Le premier utilisateur généré est écrit dans `fake_user.csv` (séparateur `;`), avec son mot de passe en clair. Utilisez-le pour vous connecter en développement :

```bash
make matcha
cat fake_user.csv
```

<Warning>
  Ce fichier contient un mot de passe en clair : il ne doit servir qu'en développement.
</Warning>

## Régénérer les données

Supprimez le volume PostgreSQL puis relancez la stack :

```bash
make down
make all
```

`seed_messages` est importé mais commenté : aucun message de chat n'est généré pour l'instant. Le fichier `seed/password_rules.py` est vide.
